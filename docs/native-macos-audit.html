Executive verdict

有明确优化空间，且先修正确性，再修“丝滑”。

当前版本适合继续开发和小数据验证，但不建议在修复 P0 与关键 P1 之前面向历史数据较多的用户发布。性能根因是“同步全量”，AI 根因是“缓存与删除缺少可验证版本语义”。

Streaming · resize · visible work

“丝滑”不是加动画，而是减少每帧必须完成的工作。

当前流式链有三份增长数据：传输无界队列、Service 累积全文、UI/DOM 累积全文。50ms batching 只能减少桥接次数，无法对前端建立背压，也无法抵消全文重解析。

SSE 到屏幕的目标链路

URLSession bytes → framed SSE parser + byte/idle limits → bounded, suspending delta channel → adaptive coalescer → one in-flight WebKit commit → stable DOM prefix + mutable tail

要求最终文本逐字节一致。缓冲区满时暂停读取或显式失败；绝不能通过 bufferingNewest 丢弃 token。

历史与可视区

  1. 空会话不创建 opacity-zero WKWebView。
  2. Mermaid/KaTeX 不进入首屏 parser-blocking bundle；按真实内容动态加载。
  3. 消息先用 content-visibility:auto 降低 layout/paint。
  4. 旧消息使用保高占位，靠 IntersectionObserver 在前后约两屏内富化。
  5. 离屏 SVG/CSS/Web Animations 暂停；回屏再恢复。

页面收缩与侧栏动画

不要用 spring 连续改变 WKWebView 的可用宽度。侧栏应放在独立 overlay layer 上，用 transform/opacity 动画；WebView 只在动画结束时接收一次最终 bounds。初始 compact 状态必须在构造 Inspector/WKWebView 前决定，避免“先创建、再关闭”的首帧抖动。

字体变化

审计没有发现需要“连续插值字体大小”的合理场景；真实 font-size 动画会触发整段文本重排。建议一次切换根级 typography token，以 100–150ms 交叉淡化旧/新层掩盖跳变，保持固定 line-height，并在 Reduce Motion 下直接切换。流式 token 本身不应改变字体度量。

截图中的“全…”

原因已定位：控件总宽固定为 150pt，扣除内边距后每项约 36pt，而真实首项是 6 个汉字“全部难度”；四个 segment 又用 maxWidth: .infinity 等分，没有最小宽度或降级规则。短期可显示“全部”，同时提供 .help("全部难度") 和完整 accessibility label；正式方案按固有宽度加权并将总宽提高到至少约 220pt，空间不足时用 ViewThatFits 切换 Menu，而不是继续截断。测试简中、繁中、英/日/德，12/14/16pt、系统显示缩放、820/1000/1700 宽度、选中 semibold、Light/Dark/High Contrast、Reduce Motion、键盘 Focus 与 VoiceOver；断言不截断且点击目标 ≥28pt。

AI timing & context

现在不是“每次全量分析”，但增量依据还不够可靠。

普通聊天已经有预算：小会话携带当前会话，超过阈值后只保留首问、context summary 和最近消息，并加入跨会话 RAG。它不会自动把全部 learning.json、错题库和提交记录塞进每次请求。

直接回答：不会每次全量

ConversationWorkspaceView.swift:290-315 组装系统提示、会话 RAG、连续性提示和预算后的当前会话；ConversationBehavior.swift:431-475 在长会话中采用“首问 + 摘要 + 最近消息”。但普通聊天 RAG 只来自 conversations，不含 learning/LeetCode；而 Messages 传输格式目前又会丢后续 system，这是准确性缺口。

AI 介入时机：脱离页面生命周期

  1. 提交进入终态且详情稳定后，按题目 debounce 并合并轨迹。
  2. 先本地确定性分类；只有出现新失败模式、代码实质变化或用户手动要求时调用 AI。
  3. 持久化队列由 app-scoped Actor 驱动，离开页面只取消 UI 观察，不取消任务所有权。
  4. 详情获取限并发 3–4；一个 batch 完成后一次持久化。
  5. 结果提交前比较 generation、submission fingerprint 和 learning revision；旧结果丢弃而非覆盖新状态。
未变化的同步当前：部分已分析 ID 会跳过，但缺少 detail/code/prompt 级失效。目标：0 次 AI 请求、0 次 embedding 重算、0 次失败计数变化。
动态及时分析当前：不稳worker 随 LeetCode 视图取消，且取消会被记失败。目标：队列独立于视图；活跃题优先，后台可暂停但不丢任务。
Messages 上下文等价当前：失败后续 system 被过滤。目标：三种 API 格式对同一逻辑 envelope 生成语义等价请求。
图片理解当前：失败只传附件标题。目标：支持的模型收到真实 image part；不支持时明确阻止或提示。
Knowledge & conversation invariants

知识点和对话必须拥有不同生命周期。

抽取后的知识点是独立学习资产，对话只是来源之一。因此删除对话不能级联删知识；删除知识则必须立即从 active 集合和未来 prompt 消失，同时 tombstone 防止自动重识别。

删除活动知识点当前：无入口原生 Bridge/UI 没有 active delete。必须补 canonical delete，并以 revision event 同步 UI、学习 prior context、图谱、计划和缓存。
外部已删除知识点当前：基本正确Electron 移入回收站后，native reload 会从 active records 排除；专用 learning prior prompt 只取 active。
永久清空回收站当前：保留 tombstonepurge/empty 只删 deleted snapshot，不删 suppressedItems；后续自动识别仍被拦截。另设显式“允许重新学习”才可清 tombstone。
恢复知识点当前：有漂移风险手写 bridge restore 没有完整执行 canonical normalize/revision/changeLog/suppression 语义。应直接调用共享 engine API。
删除对话当前：核心语义正确LegacyDataStore.swift:1148-1155 只删 conversations，随后移除会话 RAG；不修改 learning.json，已识别知识点保留。
删除对话时仍在抽取当前：测试不足需定义事务边界：先提交已确认知识，再删聊天；或取消未提交抽取。无论哪种，都不得按 conversationID 级联删除既有学习项。

Implementation sequence

三个 Gate，避免一次性大重构。

先把窗口、数据和 AI 的所有权边界修正，再做 WebKit 优化；最后处理规模化存储和共享核心。每一 Gate 都有可自动化的退出标准。

Gate A · correctness & first window

先解除阻断

  • 首窗前移除 reload/RAG sync；增加启动 signpost。
  • 修复 SubprocessRunner 原子取消与进程组清理。
  • 修复 Messages system envelope 与分析取消语义。
  • 统一 Provider URL 校验和凭据迁移。
  • 建立单实例锁。
  • 补 active knowledge delete 与 revision event。
退出：当前数据首窗 ≤ 1.2s；取消测试稳定；三种 API golden request 通过；跨客户端密钥迁移可回滚。
Gate B · streaming & interaction

再消除每帧全量工作

  • 正确 SSE framing、上限、watchdog、有界背压。
  • stable-prefix DOM 与单 in-flight WebKit commit。
  • 历史消息分层、SVG/Mermaid 可视区懒加载。
  • Inspector 用 overlay transform；筛选器自适应。
  • 修复题面双载、图谱 fingerprint、编辑器全量扫描。
  • 恢复图片多模态内容。
退出：10k 字流式回答文本完全一致；滚动/收缩 missed-frame < 1%；1000 消息首屏可交互 < 500ms。
Gate C · scale & shared core

最后解决长期增长

  • StorageActor + targeted reload；附件内容寻址。
  • SQLite/WAL 或 per-chat append log。
  • 持久化增量向量索引和内容指纹分析缓存。
  • app-scoped 分析队列、限并发详情获取、批量提交。
  • 共享 learning/SSE/provider/usage canonical 模块。
  • 账本批处理、SSH idle stop、数据 retention。
退出：10× 数据量不显著影响首窗；未变化同步 0 AI 调用；单条消息写入成本不随全库线性增长。
Acceptance metrics

用指标定义“快”和“准确”。

以下门槛应进入 CI fixture、性能基线与开发版 signpost。正式 p95 至少取 30 次冷启动，并分空数据、当前数据、10× 数据三档。

  • 首窗：p50 ≤ 0.8s，p95 ≤ 1.2s；首帧前无 >50ms 主线程任务。
  • 可交互：p95 ≤ 1.5s；RAG ready 单独记录，不与 WindowVisible 混为一项。
  • 增量索引：未变化启动 embedding 数 = 0；改单会话只更新其变更 chunks。
  • SSE：首 token→可见 p95 < 200ms；多行/分片 golden corpus 逐字节一致。
  • 背压：pending bytes 有硬上限；100k chunk 压测不出现无界 RSS 增长。
  • 流式帧率：10k/50k 字回答期间 missed-frame < 1%，WebKit long task >50ms 为 0。
  • 历史会话：1000 消息 + 50 Mermaid，最新消息可交互 < 500ms；DOM 节点数有界。
  • 窗口收缩：1700→820 宽度无连续 WebView resize；Reduce Motion 下无过渡。
  • AI 缓存：相同 fingerprint 0 请求；改一份代码只触发一个受影响 analysis。
  • 取消：所有 queue/attempt/failed 字段完全不变；500ms 后无 helper 子进程。
  • 知识删除：提交后 <200ms 从 active UI 消失；旧 ID 不进入任何新 prompt/index。
  • 对话删除：learning store byte-for-byte 不变；会话 RAG 文档为 0。
  • API 等价：Messages/Chat/Responses 的 system、text、image、tool 语义 golden test 全通过。
  • 本地化：简/繁/英/日/德 + 12/14/16pt + 820/1000/1700，无提前截断。
